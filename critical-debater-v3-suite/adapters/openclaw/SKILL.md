## Purpose / 目标

Operate **Critical Debater v3** — a LangGraph-orchestrated multi-agent adversarial
debate system with multi-model provider access, Chinese source adaptation,
deterministic evidence-credibility scoring, eight-dimension quality assessment,
and a Web UI. The heavy lifting runs as a deterministic pipeline; the agent's
role is to install, configure, launch, monitor, and interpret it.
运行 **Critical Debater v3**——LangGraph 编排的多 Agent 对抗式辩论系统,支持多模型接入、
中文信源适配、确定性证据可信度评分、八维质量评估与 Web 界面。重活由确定性流水线完成;
Agent 的职责是安装、配置、启动、监控与解读。

## Running a Debate / 运行辩论

```bash
# CLI / 命令行
PYTHONPATH=src python -m critical_debater <workspace_dir> "<topic>" [rounds] [--resume]

# Web UI + API / 界面与接口(单进程)
PYTHONPATH=src uvicorn critical_debater.api.app:create_app --factory --port 8000
```

- Resume: `--resume` (CLI) or `"resume": true` (API) continues from the
  workspace checkpoint; completed rounds are never redone.
- Cancel: `POST /api/debates/{id}/cancel` terminates at the next step boundary.
- Monitor: `WS /ws/{id}` streams audit-trail/status events; `GET /api/debates/{id}/artifacts/{name}`
  serves evidence, ledger, quality metrics, round turns, and the final report.

## Capability Routing / 能力路由

The capability documents under `capabilities/` are the debate methodology
(source-ingest, freshness-check, debate-turn, judge-audit, claim-ledger-update,
final-synthesis, …). The API-backed runner injects them into model prompts
automatically; agents and humans may read them to understand or audit the
methodology. `capabilities/debate.md` remains the entry overview.
`capabilities/` 下的能力文档是辩论方法论,运行时由 API 型 runner 自动注入模型提示词;
人与 Agent 亦可阅读以理解或审计方法学。

## Safety Boundaries / 安全边界

- No path traversal (`../`) outside the configured workspace root
- API token auth (`CRITICAL_DEBATER_API_TOKEN`) when exposed beyond localhost
- Report completion is blocked on validation failures
- The judge independently re-verifies claims and never trusts debater citations alone

## Completion Contract / 完成契约

Only declare a debate finished when:
1. `final_report.json` schema validation passes.
2. `debate_report.md` Section 8 format validation passes.
3. `quality_metrics.json` exists with all eight dimensions scored.
4. Files are atomically finalized and the audit trail records `report_generated`.
